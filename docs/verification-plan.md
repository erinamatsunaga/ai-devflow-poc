# 検証計画

## フェーズ1: 個人GitHubで一連の流れを通す
| # | ステップ | 確認すること | 結果 |
|---|---|---|---|
| 1 | リポジトリ作成・初回 push | CI と Deploy が main で走り、Pages が表示される | |
| 2 | Issue を起票 | テンプレートで受け入れ条件を書けるか | |
| 3 | AI にブランチ作成〜実装〜テスト | CLAUDE.md のルールを守るか | |
| 4 | AI に PR 作成 | テンプレートが埋まるか、CI が PR 上で走るか | |
| 5 | CI 失敗時の自己修正 | 失敗ログを読んで AI が直せるか | |
| 6 | 人間がレビュー・マージ | ブランチ保護で main 直 push が防がれるか | |
| 7 | 自動デプロイ | マージ後に Pages の build 時刻が更新されるか | |

お題の例（Issue にする）:
- 完了済みを一括削除するボタン
- Todo を localStorage に保存
- 空タイトル時にエラーメッセージを表示

## フェーズ2: 社内ルールでの検証
- `docs/rules/` に社内標準を配置
- 同じお題を再実行し、ルール準拠率・手戻り回数を比較

## 記録する指標
- 人間の介入回数／所要時間
- CI 失敗回数と AI による自己修正の成否
- ルール違反の件数と内容
